# IronLog interaction and accessibility audit — 5 September 2026

This audit covers the native iOS app in this repository (IronLog), including onboarding/authentication, workout selection, Today, saved-session editing, manual cardio, history, stats, settings, and Live Activity controls. It combines source inspection with simulator regression testing. It is a findings inventory, not a claim that every possible usability problem has been discovered or a certification of accessibility conformance.

The reported long-press-only set deletion is **not present in the audited starting revision**: both set editors already have minus buttons and confirmations. The remaining problems are small, crowded controls, weak context, and inconsistent exercise removal. Routine deletion *was* only available through a long press.

## References and method

The native platform reference is [Apple's Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines): [buttons](https://developer.apple.com/design/human-interface-guidelines/buttons), [alerts](https://developer.apple.com/design/human-interface-guidelines/alerts), [gestures](https://developer.apple.com/design/human-interface-guidelines/gestures), [accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), and [undo and redo](https://developer.apple.com/design/human-interface-guidelines/undo-and-redo). Destructive actions should communicate their consequences, conventional controls should be discoverable, and accessibility settings should be respected.

[WCAG 2.2](https://www.w3.org/TR/WCAG22/) supplies useful supporting principles: text contrast (1.4.3), use of color (1.4.1), labels/instructions (3.3.2), error identification (3.3.1), error prevention for stored data (3.3.4), name/role/value (4.1.2), and status messages (4.1.3). WCAG is a web standard; its CSS-pixel thresholds are not being represented as native iOS requirements. This change uses 44-point targets for the app's small custom controls and preserves the system's constrained Live Activity layouts.

P1 means potential loss or corruption of entered/saved work. P2 means recurring interaction, accessibility, discoverability, or feedback friction.

## Findings and changes

| ID | Priority | Finding in starting revision | Change |
| --- | --- | --- | --- |
| 01 | P1 | An exercise with no logged values disappears immediately after tapping its trash icon. | Confirm every exercise removal, including an empty exercise. |
| 02 | P2 | Set removal, completion and type icons are crowded together in the numeric entry row. | Separate numbered set/action headers from fields; provide a visible Remove label and 44-point completion control. Apply the same layout in the saved-session editor. |
| 03 | P2 | Set confirmations do not identify the set or exercise. Removing the editor's last set also removes the exercise without explaining that consequence. | Identify the set and exercise; explicitly describe last-set exercise removal in the editor. Resolve removal by stable IDs. |
| 04 | P1 | Custom confirmation overlays have no native modality/focus isolation or cancel/destructive roles. | Use native alerts attached to the presenting screens for exercise, set, workout, session, routine and data deletion. |
| 05 | P1 | Finish silently omits unfinished sets and clears the draft. | Explain what is saved and require confirmation when unfinished sets remain; cancellation preserves the workout. |
| 06 | P2 | Finish looks available when there are no valid completed sets. | Disable it and show the requirements beside the action. |
| 07 | P1 | Closing or dragging down the history editor loses unsaved edits. | Track changes, confirm explicit dismissal and prevent interactive dismissal while dirty or saving. |
| 08 | P1 | The editor dismisses even when saving is rejected; invalid rows can silently disappear if another row is valid. | Validate every row, show an actionable message, disable invalid saves and only dismiss on a successful result. |
| 09 | P1 | Repeated Save taps can initiate overlapping updates while cloud requests are pending. | Show Saving, disable repeated submissions, guard concurrent session mutations and protect dismissal during save. |
| 10 | P1 | Failed cloud deletion is ignored after removing the local session; a later sync can bring it back. Edits have an equivalent stale-copy problem. | Keep the local session/editor draft when cloud deletion fails, show retry guidance, and report failure to the presenting screen. Local-only saves/deletes remain local. |
| 11 | P2 | Failed backup looks the same as an intentionally local session. | Show “backup failed” in the session subtitle. |
| 12 | P2 | Routine deletion is hidden in a long-press menu and has no confirmation. | Add a visible routine actions menu with a native deletion confirmation. |
| 13 | P1 | Saving an existing routine name silently replaces that routine. Empty-name Save dismisses the name prompt. | Confirm replacement and disable Save for blank/whitespace-only names. |
| 14 | P2 | Numerous custom targets are 28–38 points; add-set, search and other small actions are difficult to hit. | Enlarge explicit icon targets, set inputs, add-set controls, timer controls and pills; use a native water stepper. |
| 15 | P2 | Most native screen text uses fixed font sizes. | Use semantic fonts for screen content and shared buttons/headings; stack dense groups vertically at accessibility text sizes. |
| 16 | P2 | Muted text is approximately 4:1 on the raised surface, below the normal-text 4.5:1 reference. | Raise muted gray from 0.48 to 0.56 (approximately 5.3:1 on surface2). |
| 17 | P2 | Repeated set fields lose labels after the first row; fields and icon actions lack spoken context. | Label every numeric row and speak exercise, set number and unit. Label auth, body-weight, cardio, and widget controls. |
| 18 | P2 | Selected tab, weekly activity marks and the progress chart have weak nonvisual equivalents. | Add selected-tab semantics, dated weekly summaries and a spoken chart data summary. |
| 19 | P2 | Shared buttons have no consistent disabled appearance. | Read the enabled environment in primary/secondary styles and dim disabled controls. |
| 20 | P2 | Every toast—including validation failure—triggers success feedback. Toasts disappear quickly and an old canceled task can clear a new message. | Remove blanket success feedback, announce messages to VoiceOver, extend visibility to five seconds and ignore canceled clear tasks. |
| 21 | P2 | Numeric keyboards have no reliable Done action in views outside a navigation container. Auth content cannot scroll above the keyboard. | Add a keyboard-visible dismissal bar and interactive keyboard dismissal; make authentication scrollable. |
| 22 | P1 | A comma decimal weight is stripped into a different number (60,5 becomes 605). | Normalize the separator and use finite decimal parsing; test the entered and saved value behavior. |
| 23 | P1 | Invalid optional cardio numbers silently become zero, and nonfinite/huge values can reach integer conversion. Invalid calorie overrides fall back to an estimate without explaining why. | Reject malformed/range-invalid values, show specific correction guidance and disable saving until corrected or cleared. |
| 24 | P1 | Changing units while a manual cardio draft is open reinterprets the existing distance. | Convert the draft distance from the previous unit to the selected unit. |
| 25 | P2 | Clearing body weight leaves its old stored value active. | Empty input clears the stored weight and calorie estimate; invalid values get visible guidance. Data deletion also clears in-memory body weight. |
| 26 | P2 | Notification status stays stale after visiting iOS Settings, and an undecided status looks enabled. | Refresh on scene activation and show undecided status neutrally. |
| 27 | P2 | Eight water icons overflow small layouts and tapping a filled glass unexpectedly changes the whole count. | Replace them with a labeled, bounded native increment/decrement stepper. |
| 28 | P2 | The exercise browser truncates results and requires users to guess a narrower query. | Add a Show More action; reset pagination when query/filter changes. |
| 29 | P2 | Previous-workout values appear as input placeholders and can be mistaken for entered values. | Keep previous results in the explicit Last reference line; use neutral placeholders for empty fields. |
| 30 | P2 | Horizontal swipes anywhere in the main pager can change tabs while interacting with content. | Use explicit tab navigation while preserving each tab's view and draft state. |
| 31 | P2 | A note-only/empty active workout can be mistaken for “no workout” when its add form is closed. | Decide the empty state using the actual active-workout state. |
| 32 | P2 | Spring/transition animations outside entrance effects ignore Reduce Motion. | Disable view-tree animation transactions when the setting is enabled. |
| 33 | P2 | Duplicate weekday IDs make repeated T/S labels unstable. | Give weekday positions unique identities. |
| 34 | P1 | “Delete Account & Data” promises account deletion, but the service only deletes workout records. Failure feedback is also obscured beneath Settings. | Rename the action/confirmation to Delete Workout Data, explicitly state that the sign-in account remains, provide support guidance and display failures inside the sheet. | 35 | P2 | The library failure message tells users to rebuild a release package. | Offer the usable free-workout path and direct users to Support. |
| 36 | P2 | Authentication applies sign-up password-length rules to sign-in and provides little loading guidance. | Restrict the minimum-length rule to sign-up, explain it there, show loading text and prevent changing auth mode during a request. |

## Validation

The PR includes regression tests for deletion confirmation/cancellation, identifying set removal, unfinished-set saving, preserving invalid/unsaved editor changes, decimal-comma entry, strict session validation, malformed cardio input and toast cancellation. Existing workout creation, history editing, settings/units, cardio and workout-wizard tests are also run. Results: 117 unit tests passed. Twelve UI scenarios passed in the full acceptance run; the remaining routine scenario passed in a focused rerun after moving naming/replacement into a native form (13 UI scenarios verified in total). Debug simulator builds and `git diff --check` passed. Visual inspection included the workout screen and the Stats screen at the largest accessibility text size; navigation text was constrained to a single line after that review. Full manual interaction on the second, smaller simulator was limited by an outstanding OS notification prompt and unavailable desktop-control permissions.

Reproduce with `xcodebuild -scheme IronLog -configuration Debug -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -parallel-testing-enabled NO test CODE_SIGNING_ALLOWED=NO`.

## Boundaries and follow-up

- This is a source and simulator audit, not user research or an exhaustive accessibility certification. Physical-device VoiceOver, Switch Control, all text-size/language combinations, notification delivery and lock-screen behavior need device validation.
- **Account deletion:** the existing Supabase service deletes rows, not the authentication identity. The PR fixes the misleading UI. Complete self-service account deletion requires an authenticated backend endpoint and deployment; no administrative credentials or such endpoint are present in this repository.
- **Cloud atomicity:** existing cloud replacement deletes child rows and then the parent in separate requests. The PR stops ignoring failures and preserves local work. It does not make those backend operations atomic or add an offline deletion queue; partial remote success still needs backend reconciliation.
- Recovery and authentication deliverability were inspected in code, but no real user account was created/deleted and no production workout data was mutated during validation.
